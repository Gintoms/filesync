# filesync — 技术设计

> 2026-09-22：采用 Rust 技术栈。本文是目标设计；已实现和未实现内容以 `../README.md` 为准。
> 原 Go/bbolt 方案、三平台内存估算、多层中转、等待所有下游送达后才回收旧内容的方案已被替代。

## 1. 已确认的业务边界

- 只有上游 → 下游两层；同一节点不能同时发布和订阅，不支持中转。
- 一个上游对所有下游发布相同清单；各下游分别决定本机目标位置。
- 未命中映射的文件进入待定，目标为空，不下载内容。
- 精确映射认领单个文件；以 `/` 结尾的前缀映射同时覆盖未来新增文件。
- 下游离线恢复只接收最新内容，不补中间版本。
- 下游覆盖前备份，每个目标文件保留最近 3 份；替换成功后再删除超额备份。
- 多来源映射到同一个目标文件时提示冲突，不自动相互覆盖。
- 上游删除不传播到下游磁盘，只标记为已失效。
- 中心保留每个上游发布路径的最新内容和上一版；送达回执用于展示，不作为更旧版本回收前提。

## 2. 技术栈

| 部分 | 选择 | 约束 |
|---|---|---|
| 后台语言 | Rust，工具链由 `rust-toolchain.toml` 固定 | 后台与桌面壳分别使用锁文件 |
| 调度 | Tokio | agent 使用 current-thread runtime，限制阻塞工作线程与任务队列 |
| 中心 API | Axum + rustls | 非回环默认要求 HTTPS；可显式 allow_http 启用 HTTP |
| 客户端 | Reqwest + rustls | 复用连接；流式上传下载；不接受跳过证书验证 |
| 元数据 | SQLite + rusqlite bundled | 数据库随程序链接，不需用户安装；限制缓存，关闭 mmap |
| 文件内容 | 中心磁盘目录 | 内容按 SHA-256 寻址；不将大文件放进数据库 |
| TUI | Ratatui + Crossterm | 与 agent 分进程；通过本机控制 API 操作 |
| 中心 Web | Vue 3 + TypeScript + Vite | 静态资源编入中心程序，同源调用管理 API |
| 节点桌面 | Tauri 2 + Vue 3 + TypeScript | 独立桌面进程；系统文件选择器、托盘；Rust 桥接调用本机控制 API |
| 配置 | TOML + serde | 工具不写用户配置；校验成功再整体应用 |
| 校验 | SHA-256 | 上传中心与落地之前核验内容 |
| 日志 | tracing | 日志输出 stderr，脚本结果输出 stdout |

不使用消息队列、外置数据库或对象存储。规模为 20 台以内、GB 级，中心直接管理任务元数据和磁盘文件。

## 3. 运行形态

后台保留独立可执行文件，以子命令运行不同进程；另交付包含该后台程序的 Tauri 桌面包：

```text
filesync hub                 中心服务
filesync agent               后台同步
filesync                     终端界面
filesync status / pending    JSON 查询
filesync claim               单文件或前缀认领
filesync admin               中心管理命令
FileSync.app / 桌面安装包     图形界面，自动启动或连接本机 agent
```

TUI 退出只结束界面进程。桌面窗口关闭后隐藏到托盘，退出桌面进程也不结束独立 agent。首次连接可填写节点凭证生成应用自己的配置，也可导入已有 TOML；运行时操作不改写导入的 TOML。agent 后续通过 launchd / systemd / Windows Service 接入系统服务。

```text
上游本机 → 上游 agent → HTTP/HTTPS → hub 的内容目录
                                           ↓ HTTP/HTTPS
下游本机 ← 下游 agent ← 映射、待定与下载判断
                 ↑
          本机控制 API ← Tauri 桌面 / TUI / CLI
```

上游下线不影响下游获取已上传中心的内容。

## 4. 数据与发布边界

中心保存：节点、节点认证摘要、上下游关系、当前发布清单、内容对象、送达回执。agent 保存：扫描缓存、交互认领规则、待定与落地状态。

文件身份为 `(upstream_id, logical_path)`，内容版本为 SHA-256。每个发布源指定稳定的 `prefix`，避免两个目录恰好同名时悄悄混合。

扫描使用逐项目录迭代与数据库游标，禁止先把整个目录树收集到内存。`size + mtime` 仅作为增量预筛；它不是绝对内容完整性的证明。上传和落地以哈希为准，保留未来定期完整复核入口。

完整扫描失败时保留原发布清单。内容上传成功后再提交整个清单；提交使用数据库事务。清单采用逐行 JSON，结束标记必须存在，截断清单不得触发“文件已删除”。

读取端获取一致的清单快照。当前开发版本以磁盘临时文件生成快照后流式传输，避免把全部清单装入进程内存。

## 5. 认领、冲突和备份

- 用户手写规则存于 `config.toml`；界面认领存于 SQLite `claims`，桌面发布源存于 `sources`，运行时不写 TOML。
- 对完全相同的 `(upstream, from)`，手写规则替代交互规则；合并后精确匹配优先，再取最长前缀。
- 删除手写规则可能重新显露同键的交互规则；正式配置界面须展示来源，并提供清除交互规则的操作。该交互尚待实现。
- 目标路径只允许用户给出的绝对路径/目录；校验相对路径，拒绝穿越、符号链接和跨平台保留名。
- 所有上游清单解析完后先检查目标冲突，再执行写入。
- 内容先写目标目录中的临时文件，校验 SHA-256 和长度，备份旧文件，再原子替换。
- 只在替换成功后清理多余备份，最多保留 3 份。

开发版本采用逐级路径检查；生产前还需完善句柄相对访问，处理其他进程并发替换目录的竞态，以及 Unicode、Windows junction 等平台差异。

## 6. 中心保留最近两版

文件身份为 `(upstream_id, logical_path)`。`files` 保存最新版，`hub_previous` 保存上一个不同内容版本；相同内容重复发布不轮换。内容对象按 SHA-256 共用，下游仍只接收最新版，不提供中心回滚界面。

新对象上传校验成功后写入磁盘；完整清单在事务内把变化文件的当前引用转为上一版，再切换当前引用。无完整结束标记、重复路径或缺失内容会回滚，保留原来的两版。撤下路径或删除节点会移除对应版本引用；下游已有文件保留。

上传完成/HEAD 确认可用的内容带有按节点记录的 24 小时租约；对应内容成功发布后消费本节点的租约，其他节点的租约仍保留。未完成发布的上传超时后可清理。超过租约时限才提交且对象已被回收时，本轮发布失败并保留原清单，下轮重新上传。

清理在成功发布后执行，并每 60 秒补扫（包含启动时）。逐对象检查所有当前引用、上一版引用、上传租约和在途下载保护；最终检查及删除与上传安装/发布/下载打开共用数据库互斥锁。下载响应持有内容引用，直到完成或中断后释放；删除失败记录日志并在下一轮重试。日志记录被删除的 SHA-256 和释放字节数。中心数据目录使用独占进程锁，禁止多个中心同时回收同一目录。

升级旧库时只能识别现有最新清单，不能恢复过去未记录的路径历史。从下一次更新开始形成两版记录。旧库中无引用的遗留内容按修改时间给予最多 24 小时保护，不会因重启延长；之后自动回收。暂存上传和在途传输可能让瞬时磁盘占用超过两版总量。

## 7. 认证和服务边界

目标：超管本地账号管理节点注册，节点持有独立凭证；关系变更必须影响中心的每次授权判断。

当前基础版使用管理员环境变量令牌创建节点，返回独立随机节点令牌；数据库只存令牌摘要。令牌不是最终的一次性 enrollment 流程。账号密码、凭证吊销与审计待补齐。

中心支持 HTTP 和 HTTPS。非回环监听默认要求 HTTPS；用户可显式配置 `allow_http = true` 允许 HTTP，令牌和文件将明文传输。客户端按填写的 `http://` 或 `https://` 地址连接，不强制局域网 HTTPS；HTTPS 仍验证证书。上传者必须有下游；清单、内容和回执必须满足当前上下游关系，不能只凭 SHA-256 访问任意内容。

本机控制服务绑定 `127.0.0.1` 的动态端口，用节点令牌认证；`control.addr` 仅保存端口，不保存令牌。TUI 不直接访问数据库。每个数据目录用文件锁限制一个 agent。

## 8. 内存和可靠性验收

20 MB 仅限制 agent 进程，包括 TLS、数据库、线程、扫描和实际传输开销；hub、TUI、桌面壳与 WebView 分别测量。暂按更严格的 `20,000,000 bytes` 比较，报告同时写明 MB 与 MiB。

必须实测：

1. 空闲 agent。
2. 2 万文件，含单个大目录，扫描期间并行传输接近 100 MB 的文件。
3. 数据库长期增长、重复同步、TLS 重连以及失败重试。
4. TUI 开关时后台不停止。
5. Windows、macOS、Linux 各自的进程驻留/工作集指标、操作系统版本和构建参数。

固定缓冲、受限并发与缓存是实现措施，不是达标证明。当前顺序传输只代表并发数 1，不可据此宣称并发同步或三平台内存已通过。

断点续传后续按不可变内容 SHA-256 绑定偏移量，必须校验响应范围与最终完整哈希。当前基础版失败后重试整个文件，尚不具备续传验收条件。

## 9. 实现顺序

1. 可构建单程序、TOML、SQLite、hub/agent/TUI 入口。
2. HTTPS 发布、待定、认领、下载、更新备份、删除保留、冲突检查的基础闭环。
3. 在真实 agent 上做内存测量，优先解决超预算点。
4. 续传、增量清单、快速配置热重载。
5. 文件浏览器、发布配置界面、分发矩阵、通知、语言切换。
6. 系统服务、注册与账号、三平台安装包和实机验收。
