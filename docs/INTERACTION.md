# filesync — 交互与接口

> 2026-09-22：两层结构，Rust 方案。目标交互与当前开发接口分开列出，完整交付仍以 REQUIREMENTS.md 验收。

## 1. 用户动作

| 用户 | 动作 | 结果 |
|---|---|---|
| 超管 | 注册节点、建立上游 → 下游关系 | 拒绝自连和第三层；节点自动推导职责 |
| 上游 | 选择本机文件/目录发布 | 同一发布清单向所有直接下游开放 |
| 下游 | 查看待定文件 | 目标为空，不下载内容 |
| 下游 | 认领单个文件 | 为该文件建立精确目标映射，立即安排同步 |
| 下游 | 批量认领上游前缀 | 当前与未来同前缀文件自动落到所选目录 |
| 下游 | 处理多来源冲突 | 修改保存位置，不能自动互相覆盖 |
| 上游 | 查看送达矩阵 | 对照当前 SHA-256 判断下游是否收到最新版 |
| 任意用户 | 关闭 TUI | 后台继续运行 |

## 2. 当前本机控制接口

agent 绑定动态回环端口，使用 Bearer 令牌；端口文件只有地址。Tauri 桌面、TUI/CLI 使用同一接口，禁止直接写 agent 数据库。桌面凭证由 Rust 桥接层读取，不传给网页脚本；允许的本机请求路径和方法有白名单。

| 接口 | 作用 | 当前限制 |
|---|---|---|
| `GET /status` | 最近一轮同步结果或错误 | 没有完整心跳与历史统计 |
| `GET /pending` | 待定、冲突、失败记录 | 当前最多返回 100 条，尚无分页 |
| `POST /claim` | `{upstream, from, to}`；from 以 `/` 结尾表示前缀 | 保存到 SQLite，不修改 TOML；唤醒同步循环 |

## 3. 当前中心接口

| 接口 | 授权 | 作用 |
|---|---|---|
| `GET /health` | 无敏感信息 | 健康检查 |
| `POST /v1/nodes` | 管理员令牌 | 创建节点，返回独立随机凭证 |
| `POST /v1/edges` | 管理员令牌 | 建立两层关系 |
| `GET /v1/relations` | 节点令牌 | 查询自己的上下游 |
| `HEAD /v1/blobs/{sha}` | 发布节点 | 查询自己已发布的内容，避免重复上传 |
| `PUT /v1/blobs/{sha}` | 发布节点 | 流式接收、校验后保存内容 |
| `PUT /v1/manifest` | 发布节点 | 事务替换发布清单，必须带完整结束标记 |
| `GET /v1/manifest/{node}` | 该节点的直接下游 | 获取完整发布快照 |
| `GET /v1/content/{upstream}/{sha}` | 该节点的直接下游 | 下载该上游当前发布的内容 |
| `POST /v1/receipts` | 对应下游 | 上报成功落地的当前版本 |

创建节点直接返回长期凭证只是开发基础，尚不是最终的一次性注册流程。中心暂不提供密码账号、凭证撤销、删边或审计界面。

## 4. 完整版需要补齐的交互

- 本机目录浏览与多选、发布预览、包含/排除规则、停用发布。
- 待定分页与搜索、忽略、精确的全选与前缀认领语义。
- 新增高亮、选中行与滚动位置稳定。
- 快照与事件的序号机制；连接恢复后重新获取状态。
- 来源可见的有效配置、导出与交互规则删除；配置出错保留上一有效版本。
- 传输暂停、续传、限速、错误重试与系统通知。
- 两层关系管理、送达矩阵、审计、中文/英文切换。

## 5. 交互约束

首次认领明确说明后续自动更新及最近 3 份备份，不逐次询问正常更新。冲突、手动清理和删边需要明确操作。

未认领文件只保存元数据；上游文件撤下只更新本地状态，不删除用户文件。送达回执失败需要补报，不能把已成功落盘改成失败或重新覆盖。

本机浏览器与 agent 的运行账户和访问权限必须匹配；不能假设系统服务自动拥有登录用户的所有文件权限。系统服务安装阶段需要验证这个边界。
